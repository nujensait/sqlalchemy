## Общие требования

### Инструкция

1. 📥 Переключитесь в PyCharm на ветку `main` и обновите её с помощью `Update Project...`
2. 🌿 Создайте новую ветку под названием `project`.
3. 💻 Напишите код, необходимый для сдачи итогового проекта (итоговый проект и критерии находятся в разделе "Итоговый проект").
4. ✨ Выполните автоформатирование кода:
```
uv run ruff format
uv run ruff check --fix
```

📍Если есть ошибки — исправьте.

5. 🔀 Выполните PR под названием `project` в ветку `main` и добавьте преподавателя в `Reviewers`.

### Общие критерии

#### 1. ⚙️ Функциональность.
- Прохождение тестов или проверка с верным ответом.
- Соответствие заданию.
- Отсутствие ошибок исполнения: код не падает с `SyntaxError`, `NameError`, `TypeError` или `AttributeError` при стандартных входных данных.

#### 2. 📖 PEP8 (читаемость и стиль).
- Замечания, связанные со стандартом PEP8 (например, избыточное количество пробелов, отступов или символов в строке, некорректные названия переменных).
- Проверяется при помощи `uv run ruff check`.

#### 3. 🧠 Логика и структура.
- Соблюдение принципов разработки кода:
  - **YAGNI** (You Aren’t Gonna Need It): не пишите код, если думаете, что он пригодится позже.
  - **DRY** (Don’t Repeat Yourself): не дублируйте код.
  - **KISS** (Keep It Simple, Stupid): не придумывайте к задаче более сложного решения, чем ей требуется.

#### 4. 🛡️ Безопасность и надёжность.
- Предварительная проверка.
- Обработка исключений.
- Закрытие ресурсов.

#### 5. 📚 Документация, аннотации и комментарии.
- Docstring для каждой функции и класса.
- Использование аннотаций в функциях, методах и переменных.
- Отсутствие закомментированного кода.
- Комментарии объясняют **ПОЧЕМУ** код написан так, а не **ЧТО** он делает (что должно быть очевидно из кода).

## Описание задания

Разработайте свою базу данных (SQLite) с помощью паттерна **Репозиторий** и **Unit Of Work**.

### Требования для таблиц

- База данных должна содержать минимум **3 таблицы**
- В таблицах присутствуют связи:
  - `one-to-many`
  - `many-to-one`
  - `many-to-many`
- Настроено **каскадное удаление** записей

### Требования для запросов

- Должны присутствовать запросы на:
  - добавление
  - удаление
  - изменение
  - получение объектов
- В запросах должны использоваться:
  - `WHERE`
  - `GROUP_BY`
  - `ORDER_BY`
  - `JOIN`
  - `EXISTS` (или `ANY`, `HAS`)
- Запросы должны быть **оптимизированы**

### Требования к проекту

Проект должен содержать код для демонстрации выполнения запросов:

> скачал проект – запустил файлик `main.py` – в консоль вывелись результаты запросов

(плюсом будет **красивый вывод**, чтобы было понятно, какой запрос какому результату соответствует).

- Для каждого класса и метода написаны **Docstring** и **Annotation**.
- **Ruff** проходит проверку (`pyproject.toml` для Ruff приведен в 1 лекции).
- Проект делать в ветке `project`. Для проверки сделать PR в ветку `main` и приложить ссылку на PR в GitHub.

> **(\*)** Для продвинутых – можете использовать PostgreSQL, предварительно развернув БД в контейнере Docker.
