# Техническое задание на разработку базы данных «Система управления онлайн-курсами»

## 1. Общие сведения

| Параметр | Значение |
|----------|----------|
| **Наименование проекта** | Разработка демонстрационной базы данных для итогового проекта по SQLAlchemy |
| **Тип СУБД** | SQLite (опционально — PostgreSQL в Docker-контейнере) |
| **Архитектурный паттерн** | Репозиторий + Unit of Work |
| **Цель создания** | Демонстрация навыков проектирования реляционной БД, связей между таблицами, каскадного удаления и оптимизированных запросов |

---

## 2. Функциональные требования

База данных должна обеспечивать хранение и управление информацией об:

- студентах онлайн-школы;
- курсах, доступных для изучения;
- преподавателях, ведущих курсы;
- записях студентов на курсы (успеваемость, статус завершения).

---

## 3. Состав базы данных

База данных должна содержать **минимум 4 таблицы** (фактически 4), реализующих следующие типы связей:

- **one‑to‑many** (один‑ко‑многим)
- **many‑to‑one** (многие‑к‑одному)
- **many‑to‑many** (многие‑ко‑многим) — через промежуточную таблицу

### 3.1. Таблица `students`

Хранит информацию о студентах.

| Поле | Тип | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | Уникальный идентификатор студента |
| `email` | STRING | NOT NULL, UNIQUE | Адрес электронной почты (используется как логин) |
| `full_name` | STRING | NOT NULL | Полное имя студента |
| `enrolled_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | Дата и время регистрации в системе |
| `is_active` | BOOLEAN | DEFAULT 1 | Статус активности (1 — активен, 0 — заблокирован) |

**Связи:**
- `one‑to‑many` с таблицей `enrollments` (один студент может быть записан на много курсов)

---

### 3.2. Таблица `teachers`

Хранит информацию о преподавателях.

| Поле | Тип | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | Уникальный идентификатор преподавателя |
| `full_name` | STRING | NOT NULL | Полное имя преподавателя |
| `department` | STRING | NOT NULL | Название кафедры (например, Math, CS, Physics) |
| `hire_date` | DATE | — | Дата найма на работу |
| `phone` | STRING(15) | UNIQUE | Номер телефона (уникальный) |

**Связи:**
- `one‑to‑many` с таблицей `courses` (один преподаватель может вести несколько курсов)

---

### 3.3. Таблица `courses`

Хранит информацию об учебных курсах.

| Поле | Тип | Ограничения | Описание |
|------|-----|-------------|----------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | Уникальный идентификатор курса |
| `title` | STRING | NOT NULL, UNIQUE | Название курса |
| `description` | TEXT | — | Подробное описание содержания курса |
| `credits` | INTEGER | DEFAULT 3 | Количество кредитных часов (от 1 до 6) |
| `max_seats` | INTEGER | DEFAULT 30 | Максимальное количество студентов, которое может быть записано на курс |
| `price` | FLOAT | DEFAULT 0.0 | Стоимость курса в рублях |
| `teacher_id` | INTEGER | FOREIGN KEY (`teachers.id`) | Идентификатор преподавателя, ведущего курс |

**Связи:**
- `many‑to‑one` с таблицей `teachers` (много курсов ведёт один преподаватель)
- `one‑to‑many` с таблицей `enrollments` (один курс может содержать много записей студентов)

**Каскадные действия:**
- При удалении преподавателя — `ON DELETE SET NULL` (курс остаётся, но `teacher_id` становится `NULL`)

---

### 3.4. Таблица `enrollments`

Промежуточная (связующая) таблица для реализации связи `many‑to‑many` между студентами и курсами.

| Поле | Тип | Ограничения | Описание |
|------|-----|-------------|----------|
| `student_id` | INTEGER | PRIMARY KEY, FOREIGN KEY (`students.id`) | Идентификатор студента |
| `course_id` | INTEGER | PRIMARY KEY, FOREIGN KEY (`courses.id`) | Идентификатор курса |
| `enrolled_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | Дата и время записи студента на курс |
| `grade` | FLOAT | DEFAULT NULL | Оценка за курс (от 0 до 100) — `NULL` означает, что оценка ещё не выставлена |
| `is_completed` | BOOLEAN | DEFAULT 0 | Флаг завершения курса (1 — завершён, 0 — в процессе) |

**Составной первичный ключ:** (`student_id`, `course_id`)

**Связи:**
- `many‑to‑one` с таблицей `students` (много записей может принадлежать одному студенту)
- `many‑to‑one` с таблицей `courses` (много записей может относиться к одному курсу)

**Каскадные действия:**
- При удалении студента — `ON DELETE CASCADE` (все его записи о курсах удаляются)
- При удалении курса — `ON DELETE CASCADE` (все записи студентов на этот курс удаляются)

## 4. Требования к запросам

В рамках демонстрационного проекта должны быть реализованы следующие типы запросов (через SQLAlchemy ORM):

### 4.1. Базовые операции CRUD

| Операция | Требование |
|----------|-------------|
| `INSERT` | Добавление нового студента, преподавателя, курса, записи на курс |
| `UPDATE` | Изменение цены курса, проставление оценки студенту, обновление статуса активности студента |
| `DELETE` | Удаление студента (с каскадным удалением его записей `enrollments`), удаление курса, удаление преподавателя |

### 4.2. Обязательные конструкции в запросах

| Конструкция | Пример применения |
|-------------|-------------------|
| `WHERE` | Найти всех активных студентов, записанных на конкретный курс |
| `JOIN` | Вывести список студентов с названиями курсов, на которые они записаны, и именами преподавателей |
| `GROUP BY` | Подсчитать количество студентов на каждом курсе или среднюю оценку по курсам |
| `ORDER BY` | Отсортировать курсы по популярности (количеству студентов) или по цене |
| `EXISTS` / `ANY` | Найти студентов, у которых есть хотя бы один незавершённый курс (где `grade IS NULL` или `is_completed = 0`) |

### 4.3. Требование к оптимизации

- Запросы должны использовать **индексы** на внешних ключах (`teacher_id`, `student_id`, `course_id`).
- Не допускаются N+1 запросы — использовать `joinedload` или `selectinload` там, где это необходимо.
- Агрегирующие запросы (`GROUP BY`, `COUNT`, `AVG`) должны выполняться на стороне базы данных, а не в Python.

## 5. Нефункциональные требования

| Категория | Требование |
|-----------|-------------|
| **Запуск** | Проект должен запускаться командой `python main.py` без дополнительных ручных действий |
| **Вывод** | Консольный вывод должен быть **форматирован и подписан** — понятно, какой результат соответствует какому запросу |
| **Документация** | Каждый класс и метод должны содержать **docstring** на русском или английском языке |
| **Аннотации типов** | Обязательны для всех функций, методов и переменных класса |
| **PEP8** | Код должен проходить проверку `ruff` без ошибок (конфигурация из лекции 1) |
| **Каскадное удаление** | Настроено для связей `enrollments` → `students`/`courses` |
| **Структура** | Таблицы не должны копировать структуру из учебных примеров (библиотека, книжный магазин, пользователи с доставкой) |
